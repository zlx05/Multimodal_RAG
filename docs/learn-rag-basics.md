## 1. RAG 是什么？为什么需要？

### 1.1 大模型的两个短板

大模型（LLM）很聪明，但它有两个固有短板：

1. **不知道你的私有资料**。你可以问它"高等数学里泰勒公式是什么"，它知道（训练过），但问"你昨晚记的错题里那道极限题怎么解"，它完全不知道——因为那是你的私有数据，不在它的训练集里。
2. **会编造（幻觉）**。遇到不知道的问题，它可能一本正经地编一个答案，看起来合理但实际是错的。

### 1.2 RAG 的解决思路

**RAG（Retrieval-Augmented Generation，检索增强生成）** 的思路非常朴素：

> 回答之前，先从你的知识库里**检索**出相关的内容，把检索到的内容作为"参考资料"给模型，让模型**基于资料**回答。

```
用户提问："泰勒公式的余项是什么？"
  -> 从知识库检索出讲泰勒公式的段落   （检索 Retrieval）
  -> 把段落 + 问题一起给 LLM           （增强 Augmented）
  -> LLM 基于段落生成答案               （生成 Generation）
```

这样两个问题都解决了：
- **私有资料**：检索到你的笔记内容，模型就有依据了。
- **幻觉**：答案基于检索到的资料，而且可以附上出处，用户能复核。

### 1.3 RAG vs 微调 vs 纯靠模型

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 纯靠模型 | 简单 | 不知道私有资料，会幻觉 |
| 微调 | 让模型"记住"特定风格 | 贵、慢、模型更新要重训 |
| **RAG** | 灵活、资料随时更新、可溯源 | 检索质量决定回答质量 |

RAG 的核心理念：**不改变模型，改变给模型看什么**。资料更新了，重新入库即可，模型不用动。

## 2. RAG 完整数据流

一条数据从上传到回答，分两个阶段：

### 阶段 A：入库（Indexing，一次性）

```
原始资料（PDF / 图片 / Markdown / 错题截图）
  -> 解析（多模态：文本直接读，图片 OCR）
  -> 分块（切成长度合适的小段，保留知识点边界）
  -> 向量化（每段转成一个向量）
  -> 存入向量数据库（Milvus）
  -> 同时建关键词索引（BM25）
```

### 阶段 B：问答（Retrieval + Generation，每次查询）

```
用户问题
  -> 向量化
  -> 向量检索（语义相关）
  -> 关键词检索（BM25，精确匹配）
  -> 融合（RRF）
  -> 取 Top-K 相关片段
  -> 作为上下文给 LLM
  -> LLM 生成带来源的答案
```

## 3. 核心概念逐个讲

### 3.1 Embedding（向量化）

**一句话**：把一段文字变成一个数字列表（向量），让"意思相近的文字"的向量在空间里也靠近。

比如：
```
"泰勒公式"        -> [0.12, -0.33, 0.87, ...]
"泰勒展开"        -> [0.11, -0.31, 0.85, ...]  （语义相近，向量也接近）
"矩阵的秩"        -> [0.45, 0.21, -0.66, ...]  （语义不同，向量差很远）
```

向量化用的模型叫 **Embedding 模型**。本项目用 **BGE-small-zh-v1.5**，中文效果好、体积小，输出 512 维向量。

**为什么向量能表示语义？** 因为 Embedding 模型是在海量文本上训练的，学会了"哪些词经常一起出现"。这个训练让向量空间里相近的位置对应相近的含义。

### 3.2 向量数据库（Milvus）

存向量的数据库。普通数据库存数字、文字，向量数据库专门存"向量 + 附带元数据"，并支持高效的**相似度检索**（找到和查询向量最接近的 N 个）。

本项目用 **Milvus**：
- 存每个 chunk 的向量 + 溯源元数据（文件名、页码、标题路径）。
- 查询时用余弦相似度找最接近的向量。

相似度公式（余弦相似度）：
```
cosine(a, b) = a·b / (|a| × |b|)
```
值越接近 1，两个向量方向越一致（语义越相近）。向量归一化后，直接用点积即可。

### 3.3 分块（Chunking）

向量化之前，要把长文档切成小段。为什么不能整篇向量化？因为：
1. **向量检索精度**：整篇文档一个向量，没法定位到"具体哪段讲泰勒公式"。
2. **模型上下文限制**：LLM 一次只能看有限长度，整篇塞不进去。

分块的学问在于**切在哪**：
- 粗暴按固定长度切 → 可能把"定义"和"公式"切断，一个知识点碎成两半，检索时都只召回一半。
- 按标题层级切 → 一个知识点完整保留，检索准。

本项目用 markdown 分块器按标题切 + 语义分块器按语义边界切，就是"知识点感知分块"。

### 3.4 检索（Retrieval）

检索是 RAG 的灵魂，检索质量决定回答质量。两类检索互补：

| 方式 | 擅长 | 弱点 |
| --- | --- | --- |
| 向量检索（语义） | "求极限有什么方法"这种口语化问法 | 专业词、公式、题号不稳定 |
| BM25（关键词） | "泰勒公式""例题3-2""拉格朗日"精确词 | 不懂语义 |

**混合检索** = 两路都查 + 融合，兼顾两者。融合用 RRF（倒数排名融合），看排名不看分数。

### 3.5 生成（Generation）

把检索到的 Top-K 片段作为上下文拼进 Prompt，给 LLM：

```
系统：请基于以下资料回答。资料没有则说没有。
资料：
[1] 泰勒公式是函数在某一点用多项式逼近...
[2] 拉格朗日中值定理：若 f 在 [a,b] 连续...
问题：泰勒公式的余项是什么？
```

LLM 生成答案，并标注来源编号 [1][2]，前端展示来源卡片。

## 4. 本项目怎么用 RAG 解决"学生复习"问题

### 4.1 用户痛点（为什么要做这个项目）

学生复习资料**格式杂乱、图文混杂、零散难检索**：
- 教材 PDF、Markdown 笔记、截图错题、手写笔记并存。
- 同一个知识点分散在多个资料里。
- 考前想"查一下这个知识点复习过没"，找不到。

### 4.2 本项目方案（问题 -> 方案 对照）

| 痛点 | 方案 | 对应模块 |
| --- | --- | --- |
| 格式杂乱、图片 OCR 丢失 | 多模态统一解析，OCR 图片 | 阶段1 解析器 |
| 知识点被切碎、检索不准 | 按标题/语义分块 | 分块器 |
| 专业名词、公式检索不准 | BM25 + 向量混合检索 | 阶段2 混合检索 |
| 答案没出处、无法复核 | 保存溯源元数据，回答带来源 | 溯源 |
| 资料更新要重建全库 | Redis 异步 + 内容哈希增量 | 阶段3 异步入库 |

### 4.3 技术栈全景

| 层 | 技术 | 作用 |
| --- | --- | --- |
| 前端 | Vue 3 | 上传、任务、问答界面 |
| API | FastAPI | 接口层 |
| 解析 | PyPDF + PaddleOCR | 文本 + 图片 OCR |
| 向量化 | BGE-small-zh-v1.5 | 文字变向量 |
| 向量库 | Milvus | 存向量 + 相似度检索 |
| 关键词 | rank-bm25 | 精确召回 |
| 异步 | Redis | 任务队列 + 状态 |
| LLM | OpenAI 兼容（DeepSeek/千问） | 生成答案 |

## 5. 面试问答（基础篇）

### Q1：RAG 是什么？和直接问大模型有什么区别？

**参考回答**：RAG 是检索增强生成。直接问大模型，模型不知道我的私有资料，还会幻觉。RAG 在回答前先从知识库检索相关内容作为上下文给模型，让答案有依据、可溯源。区别在于：RAG 不改变模型，改变的是"给模型看什么"。

### Q2：为什么需要 Embedding？什么是向量？

**参考回答**：把文字转成向量，让语义相近的文字在向量空间靠近，这样就能用数学方法（余弦相似度）判断两段文字是否相关。这是语义检索的基础。

### Q3：为什么不能把整本书喂给大模型？

**参考回答**：两个原因。一是模型上下文长度有限，塞不进去；二是即使塞进去，也没有"定位"能力——没法告诉用户答案来自哪一页。分块 + 向量化后，可以精准定位到"哪一段讲了泰勒公式"，还能溯源到页码。

### Q4：RAG 的瓶颈/难点在哪？

**参考回答**：主要在检索。检索错了，后面全是错的（垃圾进垃圾出）。所以项目把检索和生成拆成两个接口，单独评估召回质量。另外分块粒度、Embedding 模型选择、融合策略都会影响效果。

### Q5：这个项目最值得讲的技术点是什么？（开场白）

**参考回答**：这是一个面向学生复习场景的多模态 RAG 系统，核心解决了四个问题：多模态资料统一解析（PDF/图片/手写 OCR）、知识点感知分块、BM25+向量混合检索解决专业术语召回、回答可溯源。差异化在于针对学生复习场景，而不是通用纯文本 RAG。
