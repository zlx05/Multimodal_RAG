# 面试讲解重点

## 一句话介绍

这是一个面向学生复习场景的多模态私有知识库 RAG 系统，把教材 PDF、截图错题、手写笔记和 Markdown 资料统一解析、增量入库，并通过 BM25 与向量检索结合返回带出处的答案。

## 最值得展开的四个点

### 1. 为什么做多模态

学生资料中有大量截图错题、扫描教材和手写笔记。纯文本 RAG 会直接丢失这些内容，因此需要 OCR 文本和原图来源同时保存。

### 2. 为什么不是只做向量检索

专业术语、公式和错题编号对精确匹配敏感。BM25 负责关键词召回，向量检索负责语义召回，合并后再重排，召回稳定性优于单一路径。

### 3. 如何保证增量更新

文件保存内容哈希，Redis 记录任务状态。只有新文件或内容哈希变化时才重新解析和索引，任务失败可以重试，不阻塞上传请求。

### 4. 如何实现溯源

分块时保留文件名、文档 ID、页码、标题路径、图片路径和 OCR 区域。生成答案时只允许使用召回上下文，并把来源元数据随答案返回。

## 面试时要诚实区分

当前仓库已经完成多模态解析、Redis 异步入库、Embedding、Milvus、BM25、资料级路由和 Vue 3 界面。当前分块通过 Chunking Profile 路由技术文档、长文、版面资料、短问答和高价值资料；Contextual Retrieval 默认关闭，需要在 `.env` 中显式开启并用离线问题集验证收益。
