## 三、重排机制前后对比（当前索引内）

同一检索链路内对比：`rrf`（BM25+向量经 RRF 融合后直接取 top-k，无重排）vs `production`（路由门控 → RRF 生成候选 → `_relevance_score` 可解释重排）。

| 链路 | 变体 | Recall@1 | Recall@3 | MRR |
|---|---|---|---|---|
| 无重排（原始 RRF） | rrf | 0.4651 | 0.8837 | 0.6868 |
| 有重排（路由+relevance 打分） | production | 0.9767 | 0.9767 | 0.9826 |

结论：原始 RRF 有「榜首平局」固有缺陷（每个库的 rank-1 分数接近，跨库无法区分），重排层（`_federated_search` 路由 + `_relevance_score`）把 Recall@1 拉回生产水平，是检索质量承重的关键环节。

## 六、跨文档关系型评估（LightRAG 缺口验证）

背景：LightRAG 类图结构检索的核心卖点是**跨文档关系型/全局查询**——实体跨文档连边，回答需要拼接 2~3 份资料的问题。评估集从 7 题扩容到 **30 题**（`data/eval/questions_relational.jsonl`，每题 2~3 个期望文档，全部来自库内真实内容，覆盖 Go 语法两两桥接、数据结构×Go 跨语言对比、大创项目×传感器 PPT 跨领域 join），避免 7 题样本太小导致的指标虚高。对比两条召回链路：

- **单遍**：`_federated_search` 单遍检索，top_k=8（`scripts/eval_relational.py`）
- **ReAct**：`stage_intent`（改写+路由）+ `stage_react`（AgentExecutor 自主补检，最多 4 次追加检索 + P2.2 双路召回），收集 `ctx.fused` 全部证据（`scripts/eval_relational_react.py`）

**结论（数据驱动）**：

1. **单遍检索的关系型缺口真实存在，且比 7 题时更明显**：30 题上 `all_docs@5 = 53.3%`（7 题时 57.1% 是样本太小的虚高——扩容后约半数关系型题无法一次把所需文档全部召回到 top-5）。`mrr_any = 93.4%` 说明**入口几乎总能找到但拼接材料不全**，这正是 LightRAG 声称要解决的缺口，实测确实存在。

2. **ReAct 补检大幅收窄缺口**：`all_docs@3` 从 0.40 → 0.83（+43pp）、`all_docs@5` 从 0.53 → 0.83，`mrr_any → 1.0`（每题至少一个期望文档进证据），证据级闭环 86.7%（26/30）；单遍漏掉的期望文档被 ReAct 找回 **13 处**（每题平均 3.8 次工具调用）。**单遍∪ReAct 联合闭环 96.7%（29/30）**——生产 agent 端到端「证据齐备」的比例已接近全闭环。

3. **证据未闭环的 4 题逐题归因（召回层 vs 规划层）**：

   | 题 | 缺口文档 | 归因 | 证据 |
   |---|---|---|---|
   | rq005 join | 大创申请书（doc_24fd…） | **规划层** | agent 拿到传感器 PPT（直接答「哪种图像类型」）后仅 1 次工具调用即停手，未追溯问题点名的大创项目材料；该文档单遍检索已命中 top-8——**文档可检索，缺的是 agent 的追溯行为**（改写锚定把项目词挤出了 agent 自己的检索） |
   | rq008 synthesis | 变量（doc_7562…） | 弱期望文档 | agent 已召回的「数据类型」文档内含完整零值表（数字 0 / 切片·映射·指针 nil），问题可单文档答全——「变量」文档是权威源而非必需 |
   | rq009 synthesis | 数据类型（doc_67b9…） | 弱期望文档 | 「输入输出」文档内含完整格式动词表 + 不匹配报错（`%!d(int=1)`），问题可单文档答全 |
   | rq021 synthesis | 指针（doc_4fa9…） | 弱期望文档 | 三指针法答案自包含在已召回的数据结构文档（prev/curr/next），「指针」文档只是外围背景；这也是唯一两路都漏的文档（res=1） |

   即：**没有一个是检索层的真漏**——3 题是期望文档设得比实际需要更严（agent 单文档已能完整作答，属正确行为），1 题（rq005）是可检索但 agent 停手太早的规划层问题。

4. **LightRAG 不需要**：单遍层的关系型缺口已被 agent 补检覆盖（联合闭环 96.7%）；4 个证据缺口里 3 个是「答案自包含、图连边无可恢复内容」，1 个（rq005）是可检索性没问题、单纯规划停手。图连边对 rq005 或许有引导作用（传感器文档 → 大创项目的关系边），但 **1/30 的边际收益撑不起 LightRAG 的图索引基础设施、实体抽取管线、与 MySQL/Milvus 双写同步的运维与存储成本**。若想进一步压缺口，优先级更高、更便宜的手段是：① 问题显式引用文档/项目名时把它固定注入为检索关键词（直接针对 rq005 型规划缺口）；② 问题扩展 `QUERY_EXPANSION_ENABLED` 做了两轮评估均无净收益——**先披露测量缺陷**：第一版 `eval_relational_react.py` 漏把 `expansions` 传给 `stage_react`，扩展只记录未注入检索，30 题复测结论无效；**修正后重跑**：精确 30 题（`results_relational_react_exp30.json` vs `_fixed.json`）证据级闭环 26/30→25/30、all_docs@3 0.833→0.70，唯一残留 rq021 的恢复是 ReAct 随机补检（扩展字段为空），真正用到扩展的 rq024 反而丢闭环；**口语化题集 9 题**（`questions_broad.jsonl`——8 道有明确主题的跨文档拼接题、仅 bq001「go语言怎么学」真模糊）**单遍检索完全失效 all_docs@3=0.0**，ReAct 自主补检 8/9 闭环（丢 bq006 项目概览，两路都漏传感器 PPT），加扩展反而 7/9（bq004 拼接题被扩展拆漏「方法」子主题提前停手、bq006 仍漏）、mrr 0.91→0.76——扩展仅省工具调用 6.44→4.78（-26%）但以丢覆盖为代价；**bq001 真模糊题两次都闭环、扩展无差别，但「期望文档命中」框架测不了真模糊题（「怎么学」答案主要在库外教学法）**——**扩展子问题被 ReAct 自主补检吸收、无净收益，开关保持默认关闭**；真模糊题的正解是「证据不足反问澄清」门控（`_evidence_sufficient` 目前仅信息性、未改变行为）。

## 八、澄清门控（Phase 5）三指标对比

**目标**：把「证据不足/问题模糊时反问用户」做成真实行为（原来 `_evidence_sufficient` 只写诊断字段、从不改变回答），量化它对**所有问题**的准确率 / 召回率 / 忠诚度影响，门控 OFF（旧系统，恒硬答）vs ON（新系统，反问）。

**题集** `questions_clarification.jsonl`：10 题混合——正常题 7（rq001/rq002/rq003、bq002/bq005/bq007、切片 vs 数组）、真模糊 1（bq001「go语言怎么学」）、超纲 1（「量子计算和深度学习的关系」，库中无）、无主题 1（「给我讲讲这个吧」）。

**方法**：每题只跑一次生产检索链路（`stage_intent` + `stage_react`，与 /chat/agent 相同），对**同一份** `react.ranked` 评估 OFF/ON 两路径——隔离「门控」这一变量本身；LLM-as-judge 打准确率（是否直接正确作答，反问轮计 0）与忠诚度（RAGAS 断言验证，反问轮无事实断言判 1.0）；回答覆盖 = 1 − 反问率；检索层召回不随门控改变（同一检索）。

**关键测量发现（校准触发策略的依据）**：
1. **`EVIDENCE_WEAK_THRESHOLD=0.4` 对当前 embedding（dim=512）形同虚设**：10 题证据 best score 全部 ≥0.66（正常 0.77–0.90、超纲 0.67、无主题 0.93、真模糊 0.82），该阈值是 Phase 3 凭直觉设定、从未对当前 embedding 分布校准，按它判定门控**永不触发**。
2. **真模糊题（0.82）与无主题题（0.93）的检索得分反而最高**：「go语言怎么学」改写后能匹配到库里 Go 教程，语义距离天然近——**纯检索得分阈值物理上区分不出「真模糊」**，这是「只靠证据不足触发」策略的固有边界。
3. 据此门控触发条件扩为**「证据不足 OR LLM 判定问题模糊」**（`judge_vague_question`：不明确主题/多答案方向/无指代对象判模糊；LLM 失败默认 False 不误伤正常题），超纲/无主题/真模糊均能反问，正常题照常作答。

**三指标对比（OFF vs ON，10 题）**：

| 指标 | OFF(旧) | ON(新) | 差值 |
|---|---|---|---|
| 准确率（直接正确作答比例） | 0.8000 | 0.6000 | −0.20 |
| 忠诚度（RAGAS 断言支撑比例） | 0.5188 | 0.8250 | **+0.31** |
| 回答覆盖（=1−反问率） | 1.0 | 0.6 | −0.4 |

**触发明细（反问率 40%，4/10；理由全部为 vague）**：

| 题 | 类型 | 证据 best | OFF 忠诚度 | 澄清问题示例 |
|---|---|---|---|---|
| cls001 go语言怎么学 | 真模糊 | 0.78 | 0.31 | 想了解基础语法入门路径，还是针对特定知识点深入学？ |
| cls002 量子计算vs深度学习 | 超纲 | 0.69 | 0.63 | 想了解量子计算如何加速深度学习，还是反之？ |
| cls003 给我讲讲这个吧 | 无主题 | 0.78 | 0.56 | “这个”指资料里哪个具体内容？类型/格式化输出/运算符？ |
| cls008 写完整小程序 | 开放场景 | 0.86 | 0.06 | 用 Go 还是其他语言？命令行工具还是网页应用？ |

正常题 6 个（cls004-007/009/010）全部不触发，准确率/忠诚度与 OFF 一致（同一检索同一答案）。

**结论**：
1. **触发正确性**：真模糊/超纲/无主题 3 类全部触发反问、正常题全部不触发。三类题的证据 best score 0.69–0.86 全部 ≥0.4 阈值——纯检索阈值**永远不会**触发，LLM 模糊检测（`judge_vague_question`）补齐了这一缺口，验证了「检索到相关文档 ≠ 问题不模糊」。
2. **忠诚度 +0.31 是核心收益**：OFF 硬凑答案大量无来源断言（cls001 0.31、cls008 仅 0.06——开放题硬答几乎全编造），ON 反问轮无事实断言判 1.0 → 整体 0.52 → 0.83。门控把「高风险硬凑」换成「反问」，避免误导学生。
3. **准确率 0.80→0.60 是定义的代价，且必须结合忠诚度解读**：反问轮按定义计 0（未直接作答）；但 cls001 的 OFF 硬答被判「正确」（acc=1.0）时忠诚度仅 0.31——**表面正确实则大量编造**，单看准确率会掩盖误导风险。门控语义是「宁可不答也不误导」。
4. **边界样本 cls008（开放场景题）被判模糊**：该类题 OFF 硬答忠诚度仅 0.06，反问反而更安全，属可接受边界；若要放开，可对 judge prompt 加「有主题锚点的开放题」宽容规则。
5. **回答覆盖 0.6 是显式 trade-off**：40% 的问题先反问、澄清后再答（前端澄清 chip 一键追问），代价是首轮不产出直接答案，换回的是 4 个高误导风险硬答被消除。
